# Правила проектирования интерактивного параграфа

Правила сформулированы по итогам ревью прототипа §11 «Показательная функция». Они применяются к следующим параграфам, если для конкретной темы не принято другое решение.

## Текст

1. Не повторять одну мысль во введении, определении, формуле и примере.
2. Введение кратко описывает новый объект обычным языком и не пересказывает следующее за ним определение.
3. Удалять служебные фразы о намерениях автора, например «исследуем» или «рассмотрим», если они не сообщают математических сведений.
4. Если утверждение можно точно и кратко записать формулой, основной формой является формула.
5. Рядом с краткой формулой или записью можно поставить знак вопроса. При наведении или фокусе он показывает объяснение обычным языком.
6. Пояснение раскрывает смысл записи, а не повторяет её другими обозначениями.

## Иерархия параграфа

1. В навигации указываются номер и тема текущего параграфа.
2. Заголовок имеет вид `§11. Показательная функция`: номер и тема находятся на одной строке и имеют одинаковый визуальный уровень.
3. Заголовок не должен занимать основную часть первого экрана.
4. Базовый порядок частей: введение → определение → интерактивная анимация → свойства → пример → проверка понимания.
5. Пример располагается после объяснения и исследования темы, а не на одном уровне с определением.

## Представление информации

1. Свойства оформляются обычным списком, если между ними нет отношения, требующего карточек или схемы.
2. Табличные значения оформляются семантической таблицей, а не набором визуально похожих блоков.
3. Предупреждение или важное ограничение выделяется жёлтым цветом внимания. Красный текст не используется как основной способ такого выделения.
4. Декоративная структура не должна делать простой список сложнее для чтения.

## Интерактивная анимация

1. График должен поддерживать прямое исследование: наведение или касание любой точки кривой показывает её координаты.
2. Отдельный параметр не добавляется, если то же действие естественнее выполнить непосредственно на анимации. Поэтому для выбора точки графика не нужен ползунок аргумента.
3. Параметры анимации содержат только действия, которые изменяют математическое состояние модели.
4. Отдельный раздел переключаемых подсказок не используется. Постоянно необходимые ориентиры являются частью анимации.
5. Таблица значений пересчитывается при изменении параметров анимации.
6. Ученик может ввести собственное значение аргумента и сразу получить вычисленное значение функции.

## Проверка понимания

1. Одновременно показывается один вопрос в виде отдельной карточки.
2. После ответа открывается следующий вопрос.
3. После последнего вопроса показывается итоговый результат и краткая рекомендация.
4. Проверка понимания остаётся самостоятельной частью параграфа после объяснения и примера.

## Выбранная компоновка

Основой следующих итераций является последовательный параграф из варианта C. Он выбран за ясный порядок чтения и достаточное место для объяснения темы. Варианты A и B сохранены в истории Git и не развиваются дальше.
